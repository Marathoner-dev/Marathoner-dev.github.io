온리브 AWS 인프라

월 10만 원 상한 안에서, SSH도 장기 키도 없이 운영하는 AWS 인프라

기간
2026.10 - 진행 중
역할
설계, Terraform 코드, 운영
팀
혼자 (온리브 패스 팀)

왜 만들었나

작은 팀이 실제 결제를 받는 서비스를 운영하려면, 안 죽어야 하고 비밀이 새면 안 되고 돈도 많이 들면 안 됩니다. Fargate, ALB, NAT 게이트웨이로 정석대로 짜면 가장 작게 잡아도 월 15만 원이 넘었습니다. 그래서 비용 상한부터 정하고, 그 안에서 안전하게 운영하는 구조를 설계했습니다.

만든 것

  • 01Terraform으로 VPC, EC2, RDS, ECR, S3, SSM, CloudWatch 알람, 예산 알림까지 리소스 63개를 코드로 관리
  • 02dev와 prod 서버를 따로 운영. 환경마다 EC2 t3a.small 한 대에 Docker Compose로 API, 웹, Caddy를 올리고 Caddy가 HTTPS 인증서를 자동 발급
  • 03RDS PostgreSQL(db.t4g.micro) 한 대를 dev와 prod가 나눠 쓰되, 환경마다 DB와 계정을 따로 둬 자기 DB만 접속
  • 04배포 파이프라인도 환경별로 분리. main에 머지하면 dev에 자동 배포되고, prod 브랜치에 올리면 GitHub production 승인을 거쳐 dev에서 검증한 같은 백엔드 이미지로 prod에 배포
  • 05Organizations와 IAM Identity Center로 계정과 로그인을 관리하고 루트 계정은 MFA
  • 06서버 셸, API, DB 접속은 모두 SSM 세션과 포트 포워딩으로. 터널 스크립트로 팀원도 같은 방법을 씀

설계에서 고민한 것

비용 상한부터

dev와 prod를 합쳐 월 10만 원 안으로 정했습니다. 환경마다 EC2 t3a.small 한 대, 둘이 같이 쓰는 RDS db.t4g.micro 한 대로 예상 월 8~9만 원입니다. 사용자가 늘어날 때 옮겨 갈 Multi-AZ, Fargate 구성(월 약 54만 원)은 다음 단계로 문서에 남겨 뒀습니다.

SSH를 열지 않기

22번 포트는 닫고 80, 443만 엽니다. 서버 접속은 SSM Session Manager로만 하고, 비밀 값은 SSM Parameter Store에 둡니다.

오래 가는 키 없이 배포

GitHub Actions는 OIDC로 그때그때 역할을 받습니다. prod 배포는 GitHub의 production 승인을 거치고, prod 인프라 변경은 사람만 적용합니다.

망가져도 되돌릴 수 있게

RDS 자동 백업 7일로 초 단위 시점 복구를 하고, 삭제 방지를 켰습니다. 큰 마이그레이션 전에는 스냅샷을 찍고, CPU 80%, 남은 저장 공간 20%, 연결 수 알람과 예산 알림이 메일로 옵니다.
