Why it exists

Between school, a company, and outside activities, there is never enough time to code. So I changed how I work: during the day I decide what to build and why, and agents handle repeatable implementation and checks overnight. Merges and deploys always need a human yes.

What I built

  • 01night-shift: leave a plan in the afternoon, and Claude opens branches and draft PRs overnight, then reports in the morning.
  • 02A daily real-use check: run E2E tests in a fresh worktree, sort failures into app bugs, stale tests, and data assumptions, and fix only the first two.
  • 03content-planner, cardnews, blog-writer: turn one idea into a plan, a carousel, and a blog post at once, then review with real engagement numbers.
  • 04orca-vault: agents never see a password. It is pulled from the Keychain and typed only into allowed sites.
  • 05devlog: turn the day's work into a dev log with company details removed.

Design decisions

Stop at the pull request

Agents stop at branches and PRs. Merging, deploying, and touching production data need explicit approval every time.

Classify failures first

A failing test is classified before anything is fixed, so data problems never get papered over with code changes.

Secrets stay outside the agent

A hook blocks any command that would read the Keychain, and a password is typed only after the site origin is checked.
