왜 만들었나

학교, 회사, 대외활동을 같이 하면 코딩할 시간이 모자랍니다. 그래서 사람은 낮에 무엇을 왜 만들지 정하고, 반복되는 구현과 점검은 에이전트가 밤에 하도록 일하는 방식을 바꿨습니다. 머지와 배포는 언제나 사람이 승인합니다.

직접 만든 에이전트 스킬

만든 것

  • 01night-shift: 낮에 기획을 남기면 밤에 Claude가 브랜치와 draft PR을 만들고 아침에 보고서를 냅니다.
  • 02매일 실사용 테스트: 새 작업 공간에서 E2E 테스트를 돌리고, 실패를 앱 결함, 낡은 테스트, 데이터 전제로 나눠 앞의 두 가지만 고칩니다.
  • 03content-planner, cardnews, blog-writer: 소재 하나로 기획안, 카드뉴스, 블로그 글을 동시에 만들고 반응 수치로 회고합니다.
  • 04orca-vault: 에이전트가 비밀번호를 보지 않고, 허용된 사이트의 비밀번호 칸에만 키체인에서 꺼내 넣습니다.
  • 05devlog: 그날 개발한 내용을 회사 정보를 빼고 개발 일지로 정리합니다.

설계에서 고민한 것

PR까지만

에이전트는 브랜치와 PR까지만 만듭니다. 머지, 배포, 운영 DB 작업은 사람이 그때마다 승인합니다.

실패를 먼저 나누기

테스트가 실패하면 바로 고치지 않고 원인을 셋으로 나눕니다. 데이터 전제 문제를 코드로 덮지 않으려는 규칙입니다.

비밀은 에이전트 밖에

키체인에 있는 비밀번호를 읽는 명령은 훅으로 막고, 사이트 주소를 확인한 뒤에만 입력합니다.
